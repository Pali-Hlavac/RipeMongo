# Documents

## What it does

- A collection tab shows its documents page by page under the collection header.
- Three views of the same page, switchable per tab:
  - **List**: one card per document; nested objects and arrays expand on click; values are
    colored by type and show mongosh syntax (`ObjectId("…")`, `ISODate("…")`,
    `NumberLong("…")`); the tooltip names the BSON type. Wide documents show 25 fields, then
    "Show N more fields".
  - **JSON**: each document as pretty mongosh-style text, the same syntax the query bar
    accepts.
  - **Table**: one column per top-level field (in order of first appearance, `_id` first,
    at most 200), resizable columns, row numbers, virtualized rows; nested values show as
    "{ 3 fields }" / "[ 5 items ]".
- **Paging**: 10–1000 documents per page (default 20), previous/next, "1–20 of about 1,500".
- **Copy** a document (hover a card) as shell syntax.
- **Reload** re-runs the current page and count.
- **Find on this page** (Ctrl/Cmd+F or the toolbar magnifier) highlights text in the loaded
  documents of the current view, page only; see [search.md](search.md).
- **Query bar**: filter (always visible) plus Options for projection, sort, collation, skip,
  limit and max time; Enter or Find applies, Reset clears. Shell syntax everywhere (ADR 0012).
  A rejected query shows the backend message under the bar and marks the named part invalid.
- **Autocomplete** (ARIA combobox, no editor dependency): field paths from the loaded page
  (nested, documents in arrays), `$` operators per part (filter vs. projection; none for sort),
  collation keys, and shell constructors with the caret placed inside the quotes.
- **History and favorites** per connection + collection: successful runs are recorded (most
  recent first, duplicates moved up, 30 kept); named favorites (replaced by name, up to 100),
  managed in a dialog. Stored locally in `query-history.json`.

- **Insert** (toolbar): one document or an array of documents (up to 10,000) typed in the code
  editor; a missing `_id` is generated by the server.
- **Edit** (card button, or double-click a table row): the whole document in the code editor,
  prefilled in shell syntax. The `_id` cannot be changed; if it is left out it is kept.
- **Clone**: the insert editor prefilled with the document without its `_id`.
- **Delete**: one document after a confirmation that shows its `_id`.
- **Inline edit** (list view): double-click a value, or focus it and press Enter or F2; type
  the new value in shell syntax (`NumberLong(5)`, `"text"`, `{ a: 1 }`); Enter saves, Esc
  cancels.
- **Code editor**: Monaco, bundled locally and loaded on first use, with a mongosh syntax
  highlighter and light/dark themes; Ctrl/⌘+Enter saves; parse errors are marked at their line
  and column.
- **Safety**: writes are refused on views and read-only collections (no buttons are shown).
  Edits are optimistic-concurrency checked: if the stored document (or field) no longer
  matches what was loaded, nothing is written and a "changed since it was loaded" conflict is
  shown. While a projection is applied, whole-document edit and clone are disabled because the
  hidden fields would be lost; inline field edits and delete stay available.

- **Export** (toolbar, also on views): opens the tools feature's export dialog with the tab's
  applied filter, sort, skip and limit ([tools.md](tools.md)). **Import** (writable
  collections) opens the import dialog for the collection; the tab reloads when it ends.
- **Bulk update / delete** (toolbar "Bulk" menu, writable collections only): starts from the
  tab's applied filter.
  - **Update documents**: an update in shell syntax, either operators (`{ $set: … }`,
    `{ $inc: … }`, `{ $unset: … }`, …) or an aggregation pipeline in `[ ]`. A replacement
    document (no `$` keys) is rejected.
  - **Preview** first (button, Enter in the filter, Ctrl/⌘+Enter in the editor): how many
    documents match and the first 3, before and after. On a standalone server the "after" is
    not available and the dialog says so.
  - **Apply** only after a preview of exactly the current filter and update (editing either
    marks the preview stale and disables the button), then confirm by typing the collection
    name. A toast reports "Updated X of Y matching documents" / "Deleted N documents".

## How it works

```
CollectionTabView (app) → CollectionDocuments (documents)
  → api/queries.ts useDocumentPage / useDocumentCount (TanStack Query)
  → find_documents / count_documents
  → documents::service (FindOptions: skip, limit + 1, maxTimeMS; ejson parses query parts)
  ← FindPage { documents: canonical EJSON strings, hasMore }
  → lib/ordered-json.ts → lib/bson.ts (typed BsonValue tree) → views (lib/format.ts)
```

- Paging is stateless `skip`/`limit + 1` (ADR 0011); the count is separate and optional. The
  query's own skip/limit are applied on top of paging in the frontend (`lib/query.ts`
  `pageWindow`, `pageHasMore`, `visibleCount`).
- The query bar edits a draft; Find writes it to the tab's `query` in `store/view.ts`, which
  keys the page and count queries. Successful, non-placeholder results record the query
  (`hooks/useRecordSuccessfulQuery.ts` → `record_query`).
- Documents travel as canonical Extended JSON and are parsed in order (ADR 0012).
- Per-tab view settings (`view`, `pageSize`, `skip`) live in `store/view.ts`; query data in
  TanStack Query under `["documents", connectionId, db, collection, …]`, removed on
  disconnect or when the connection is deleted. The previous page stays visible while the
  next one loads.
- Writes: `components/actions/DocumentActionsProvider.tsx` owns the editor and delete dialogs
  and exposes the actions through a React context (`actions/context.ts`) to the list, JSON and
  table views. `api/mutations.ts` calls `insert_documents`, `replace_document`,
  `set_document_field` and `delete_document`, then refreshes the pages and the collection
  statistics. Documents are addressed by `_id` sent as canonical Extended JSON
  (`lib/identity.ts`, `lib/canonical.ts`).
- Bulk: `components/bulk/` (`BulkActionsMenu` → `BulkUpdateDialog` / `BulkDeleteDialog`,
  `PreviewSamples`), `api/bulk.ts`. Previews are TanStack queries keyed by the submitted
  filter and update (`gcTime: 0`, never retried). The backend (`documents/bulk.rs`) counts with
  `count_documents` (estimated for an empty filter) and, on replica sets and sharded clusters,
  simulates the update on the sample documents in a transaction that is always aborted, so the
  "after" is what the server would really store and server-side errors (e.g. `$inc` on a
  string) show up before anything is written.
- Concurrency check: `replace_document` receives the document as loaded and compares it with
  the stored one before `replaceOne`; `set_document_field` filters on `{ _id, path: original }`
  so a changed field matches nothing (`CONFLICT`).

## Edge cases and limitations

- Deep pages on very large collections are slower (skip); see ADR 0011.
- Counts use the metadata estimate when there is no filter ("about"); an exact count with a
  filter gives up after 10 s, and paging still works without it.
- Dates outside the JavaScript range are shown as milliseconds and copied as
  `{ $date: { $numberLong: "…" } }`.
- Suggestions only know fields of the documents on screen.
- History keeps the text parts (filter, projection, sort, collation), not skip/limit/time.
- The table shows the fields of the loaded page only; a field that appears only on other pages
  has no column until you get there.
- Documents without an `_id` (projected away) cannot be edited or deleted.
- Bulk writes are not atomic across documents and cannot be undone. The count and samples
  are from the moment of the preview; the write applies to whatever matches when it runs.
- Upserts, `arrayFilters`, hints and collation for bulk writes are not offered yet.
- Inline edit sets the whole value of a field; renaming or removing a field needs the
  document editor.

## How to test

- Rust: `pnpm test:rust` — `documents::service` unit tests, the cross-language round-trip test
  in `ejson/tests.rs`, and `tests/documents.rs` (Docker: paging, filters in shell syntax,
  projection, counts, error naming).
- Frontend: `pnpm test` — `bson.test.ts` (ordered parsing, types, shell output, previews),
  `CollectionDocuments.test.tsx` (list expand, paging, JSON and table views),
  `QueryBar.test.tsx` (run, record, suggestions, inline errors, history),
  `completion.test.ts`, `query.test.ts`; Rust `query_history/tests.rs`.
- Bulk: `tests/bulk_writes.rs` (Docker: standalone preview without "after", update with
  operators and a pipeline, replacement rejected, delete many; single-node replica set: exact
  before/after preview, nothing written, server errors surfaced in the preview),
  `documents::bulk` unit tests (update parsing), `BulkDialogs.test.tsx`, `lib/bulk.test.ts`.
- Writes: `tests/document_writes.rs` (Docker: insert one/many, duplicate key, replace keeps
  `_id`, conflicts, validator rejection, inline `$set`, delete) and
  `DocumentActions.test.tsx` (insert, edit, conflict, clone, delete, inline edit, read-only,
  projection; Monaco replaced by a textarea).
- Manual: open a collection with nested documents; switch views; change the page size and go
  to the next page. Insert, edit, clone and delete a document; change one field inline; edit
  the same document in another tool and save again to see the conflict.
